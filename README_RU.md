# Twitch Stream Alerts — GitHub Actions + Telegram + Discord

Бот отслеживает один Twitch-канал и отправляет сообщения о начале и завершении эфира в Telegram и Discord.

**Рекомендуемый режим:** GitHub Actions запускает проверку каждые 5 минут. Компьютер и VPS не нужны. Python-библиотеки устанавливать не нужно — используется стандартная библиотека Python.

## 1. Что понадобится

- аккаунт GitHub;
- Twitch Client ID и Client Secret;
- токен Telegram-бота и chat ID;
- Discord Webhook URL.

Все секретные значения будут храниться в GitHub Secrets, а не в исходном коде.

## 2. Создай приложение Twitch

1. Открой официальный раздел: <https://dev.twitch.tv/console/apps>.
2. Создай приложение (Application). Для OAuth Redirect URL можно указать `http://localhost`.
3. Сохрани `Client ID` и создай `Client Secret`.
4. Логин отслеживаемого стримера — часть адреса `https://www.twitch.tv/логин`, без `@`.

## 3. Подготовь Telegram

1. В Telegram найди `@BotFather` и выполни `/newbot`.
2. Сохрани токен, который выдаст BotFather.
3. Открой созданного бота и нажми **Start**. Для группы добавь бота в группу; для канала выдай право публиковать сообщения.
4. Получи `chat_id`. Один из способов — отправить боту сообщение, а затем открыть `https://api.telegram.org/botТВОЙ_ТОКЕН/getUpdates`.
5. Значение `message.chat.id` (или `channel_post.chat.id` для канала) — нужный chat ID.

Не публикуй ссылку `getUpdates` с токеном и не отправляй токен другим людям.

## 4. Подготовь Discord

1. Открой настройки Discord-сервера → **Интеграции** → **Вебхуки**.
2. Создай вебхук, выбери текстовый канал и скопируй его URL.
3. URL вебхука понадобится на шаге добавления GitHub Secrets.

## 5. Создай GitHub-репозиторий

1. Открой <https://github.com/new>.
2. Назови репозиторий, например `twitch-stream-alerts`.
3. Для бесплатной работы каждые 5 минут рекомендуется выбрать **Public**. Стандартные GitHub-hosted runners бесплатны в публичных репозиториях. Исходный код и файл состояния будут видны всем, поэтому в репозитории нельзя хранить токены и пароли. Токены ниже добавляются отдельно в GitHub Secrets.
4. Создай репозиторий. Не добавляй README или `.gitignore`, чтобы не возник конфликт при первой загрузке.
5. Распакуй архив и загрузи **содержимое** папки `twitch_stream_alert_bot` в корень репозитория. Важно сохранить папку `.github/workflows` и файл `.github/workflows/twitch-alerts.yml`.
6. Закоммить/сохрани файлы в основную ветку (`main`). Расписание GitHub запускается только из файла workflow, находящегося в default branch.

### Почему Public, а не Private?

GitHub не списывает минуты за стандартные GitHub-hosted runners в публичных репозиториях. В приватных репозиториях минуты учитываются, причём каждая задача и неполная минута округляются вверх. При расписании раз в 5 минут получается около 8 640 запусков за 30 дней, поэтому приватный репозиторий может выйти за бесплатный лимит. Если публичность исходного кода/состояния неприемлема, используй Private, предварительно проверив лимит и стоимость GitHub Actions в своём аккаунте.

## 6. Добавь секреты GitHub

В репозитории открой **Settings → Secrets and variables → Actions → New repository secret**. Добавь следующие секреты (имена должны быть написаны точно так):

| Name | Что вставить |
|---|---|
| `TWITCH_CLIENT_ID` | Twitch Client ID |
| `TWITCH_CLIENT_SECRET` | Twitch Client Secret |
| `TWITCH_CHANNEL_LOGIN` | Логин Twitch-канала, например `some_streamer` |
| `TELEGRAM_BOT_TOKEN` | Токен от BotFather |
| `TELEGRAM_CHAT_ID` | ID личного чата, группы или канала |
| `DISCORD_WEBHOOK_URL` | Полный URL Discord Webhook |

В GitHub Secrets ничего не нужно помещать в исходный код или `config.example.json`. Если используешь только один способ доставки, можно не добавлять секреты второго сервиса — он будет автоматически отключён. Но Twitch Client ID, Client Secret и логин канала обязательны всегда.

## 7. Включи и проверь workflow

1. Открой вкладку **Actions** репозитория.
2. Если GitHub предлагает включить Actions, нажми **I understand my workflows, go ahead and enable them**.
3. Выбери workflow **Twitch stream alerts**.
4. Нажми **Run workflow**, чтобы выполнить первую проверку вручную.
5. Открой запуск и посмотри логи шага **Check Twitch and send notifications**.
6. Далее GitHub будет запускать проверку автоматически каждые 5 минут.

Первый запуск синхронизирует начальное состояние канала. Чтобы не присылать ложное сообщение о старте уже давно идущего эфира, при первоначальной настройке бот по умолчанию не уведомляет о стриме, который уже был в эфире в момент первого запуска. Он начнёт отправлять уведомления при следующем переходе offline → online.

## 8. Как работает сохранение состояния

GitHub Actions создаёт новую среду для каждого запуска. Поэтому бот сохраняет `state.json` в репозитории. Workflow автоматически коммитит только изменения состояния: начало/конец стрима или изменение названия/категории. Счётчик зрителей не сохраняется, чтобы не создавать коммит каждые 5 минут.

Если один сервис временно недоступен, статус доставки для Telegram и Discord хранится отдельно, а недоставленное сообщение повторяется при следующем запуске.

В публичном репозитории `state.json` может показывать, находится ли канал в эфире, а также последнее название и категорию стрима. Это не секретные учётные данные, но эти сведения будут публичными.

В workflow предусмотрен heartbeat-коммит примерно раз в 30 дней: GitHub может автоматически отключить расписание публичного репозитория, если в репозитории нет активности 60 дней.

## 9. Важное про интервалы и доступность из РФ

- Частота — раз в 5 минут. GitHub поддерживает этот минимальный интервал для `schedule`.
- Это не гарантия доставки ровно минута в минуту: GitHub предупреждает, что расписание может задерживаться при высокой нагрузке. Уведомление обычно придёт при ближайшем успешном запуске.
- Сам бот обращается к Twitch, Telegram и Discord с инфраструктуры GitHub, а не из домашней сети. Это может помочь, если сайты/API недоступны у твоего провайдера в РФ.
- Однако это не обходит блокировку Telegram или Discord на устройстве получателя. Даже если GitHub успешно отправил сообщение, приложение или сайт могут не открываться в твоей сети.

## 10. Локальный запуск на Windows (необязательно)

Если захочешь запускать бота на компьютере:

1. Скопируй `config.example.json` в `config.json`.
2. Заполни параметры Twitch, Telegram и Discord.
3. Установи Python 3.10+ и запусти `run_windows.bat`.

Для локального запуска бот продолжает работать в цикле с интервалом из `config.json` (по умолчанию 60 секунд). Для GitHub Actions `config.json` не нужен — используются GitHub Secrets.

## Безопасность

- Не добавляй `config.json`, токен Telegram, Twitch Client Secret или Discord Webhook URL в публичный репозиторий.
- Если секрет случайно попал в коммит, считай его скомпрометированным: перевыпусти Telegram-токен через BotFather, создай новый Discord Webhook и новый Twitch Client Secret.
- Не отправляй мне свои токены или пароли. При необходимости помогу разобраться по скриншоту страницы настройки, предварительно скрыв секретные значения.
